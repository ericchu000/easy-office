# 本地多模态智能办公助手开发计划（Vibe Coding 自包含指导纲领）

## 总体开发目标

本项目旨在构建一款面向个人用户、兼具轻量化落地能力与企业级平滑演进潜力的通用型本地多模态智能办公助手。该系统直接面向包含数千个异构文件（涵盖 Word 文档、PDF 文档、PPT 演示文稿、Excel 工作簿、CSV 数据表以及各类图片格式）、跨越多重主题领域与不同文件体积、内含数学公式、统计图表、复杂跨页表格、多栏排版及各类表单单据的文件夹场景，提供“通用多模态知识库检索问答”与“通用多模态文档自动化操作处理”两大核心能力。系统在整体架构上划分为“核心功能板块（包含离线解析索引部分与在线智能体部分）”与“外围交互板块（包含 CLI 终端工具、Web UI 网页端、跨平台桌面端 App、ACP 协议消息网关）”两大组成部分：离线部分以 Docling 作为核心解析后端（同时通过抽象接口预留未来扩展接入 MinerU 与 DeepSeek-OCR2 等解析后端的能力），针对扫描件 PDF、原生数字版 PDF、新旧格式办公文档、照片图像、大规模 CSV 与 Excel 表格实施差异化解析与多进程任务并行化索引构建，结合“两层通用元数据（第一层系统基础属性与第二层文档级语义增强元数据）+ 三类模态专属结构摘要（办公文档专属结构摘要、图像专属结构摘要、表格专属结构摘要）”提取管道、支持“宿主机原地引用模式”与“跨端上传托管归档模式”的本地文件系统（通过抽象接口预留未来扩展 MinIO 等对象存储的能力）、面向二进制文档的本地“纯文本伴生镜像缓存”以及 SQLite 与 sqlite-vec 向量存储（通过抽象接口预留未来扩展 Elasticsearch 等检索引擎的能力）实现轻量高效的混合索引入库；在线部分建立支持并发调度与终身学习能力的智能体主循环，将统一多模态混合检索工具、文档深度检视与零样本动态结构化抽取工具、通用表格探查与受控沙箱动态编程计算工具、动态规则文件系统分类与安全归档工具、多模态视觉精筛与图表核验工具、跨通道消息与文件主动投递工具封装为六个正交、高通用性的基础原子工具，并引入基于用户使用习惯的“智能体技能自进化与沉淀功能”构建本地“用户自进化技能库”，融合结构化元数据过滤、BM25 全文分词搜索、向量语义搜索与操作系统层面的 ripgrep 极速字节流搜索工具（直接扫描原生纯文本文件与二进制文件的纯文本伴生镜像缓存），能够通过沙箱动态编写代码与高频技能自动沉淀的方式通用化解决跨模态文件查找与跨端投递、多维度文件夹自动归档整理、跨多份复杂文档动态抽取结构化指标并导出表格或写入 SQL 数据库、结构化数据表的多维清洗重塑与数学插值计算等广泛办公需求，而且在一切涉及检索的问答与处理任务中强制将检索依据（精确到源文件位置、页码、行列范围与原文片段）展示给用户，确保答案的透明性与可解释性；外围四个交互端（CLI 终端、基于 React + Vite 的 Web UI、基于 Electron 的桌面端 App、对接 Telegram / 企业微信 / 飞书 / 钉钉的 ACP 协议消息网关）均通过统一的本地核心服务接口（含全局配置管理接口、第一轨常规响应原路返回管道与第二轨跨通道通知与文件主动投递事件总线）与核心功能板块通信，彼此彻底解耦、独立开发且互不依赖。

## 全局 AI 协作规范与开发准则

编程 AI 在每个独立会话中必须严格遵循以下协作准则：

1. **偏差与灵活性处理**：各开发步骤"功能"部分与"验收标准"部分不允许偏离，如果发现计划有纰漏和错误的地方，请直接指出，讨论修改后再继续开发；"技术方案"部分是推荐的技术路线，允许你根据实际情况调整具体实现细节，前序步骤已经完成的内容尽量不要大幅修改，但是如果发现存在逻辑纰漏或与当前步骤开发内容冲突，不要硬遵守——按正确的方式调整修改后实现，并把偏差内容和理由写进开发总结的第 3 部分，后续开发步骤会以你的实现为准。

2. **坚持通用化架构与轻量化首发原则**：本系统定位为通用多模态智能办公助手，同时，对于面向未来企业级演进预留的扩展组件（如 MinIO、MinerU、DeepSeek-OCR2、Elasticsearch），当前开发阶段仅需在架构上考虑预留扩展能力，无需编写这些扩展组件的具体适配器实现，亦无需将其纳入验收测试，确保首发版本高度轻量可控。

3. **网络资源与环境安装操作红线**：禁止自行获取重度网络资源，因为很容易卡死编程 Agent。具体来说：禁止自行安装任何环境、运行时、依赖库，禁止自行下载任何外部数据、安装包、模型。如有相关的网络资源获取需求，包括下载包、数据以及安装环境，明确告知人类用户来操作（给出可照做的操作指令），等待用户确认完成后再继续。你可以正常上网查询技术资料，读写项目内的本地文件，检查环境安装情况。

4. **测试**：每个开发步骤应按照验收标准进行测试，建议测试内容分两档：
一档是给人类用户审查"业务实现有没有跑偏"用的，也就是主要从人类用户使用产品的角度，测试产品外围用户使用接口，不需要测试过于底层的代码，节约人类审查时间，建议把截至本步骤的功能串成一条端到端业务链路，以业务叙事方式编写。
另一档则是从开发者代码实现角度进行的测试，主要对代码具体实现的逻辑正确性和底层细节进行测试，测试内容偏底层具体实现。
以上两档测试，任何一档如内容过于简单，均可不编写专门的测试脚本，在开发总结中具体说明测试方法即可，但是要求测试方法具有可实操性。需要编写时，测试脚本建议以 step_xx 命名便于区分（xx 为步骤编号），同时说明测试方法和预期运行脚本的结果。

5. **开发总结**：每开发完一个步骤，且验收标准全部通过后（由于可能涉及到前序步骤代码的修改，只要求本步骤的测试通过即可，前序步骤测试脚本不要求继续通过），在 docs/PROGRESS.md 中追加本步骤的开发总结。PROGRESS.md 是后续开发会话了解前序成果的唯一桥梁，此前步骤已写入的内容不得有任何改动，只允许在文末追加。
    
    每个步骤的开发总结具体包含以下四部分，整体以逻辑清晰、连贯通顺、人类阅读友好的自然语言段落撰写，避免大段罗列源码、避免大量流水账式的条目堆砌，但要注意，每个自然段应该是一个逻辑上的整体，每部分根据需要可分多个自然段，千万不要把逻辑上不相关的内容用分号硬塞到一个自然段里。
**1）开发内容解读（总分结构）：**
先用自然语言段落讲清本步骤具体开发了什么功能项，以及这些功能项对应的代码，建议每个功能项一个自然段；然后以批注方式对本步骤的核心代码进行解读——引用关键代码片段，配以自然语言段落解释其逻辑与关键决策，而不是逐行注释或简单复述代码。
**2）完整的测试方法：**
说明两档测试对应的具体测试方法，测试覆盖了哪些行为、测试预期行为等，尽量用逻辑完整的自然段描述，不要列纯粹条目式的流水账。
**3）对开发计划和前序步骤已完成代码的调整（如有）：**
说明对开发计划和前序步骤已完成代码具体调整了什么内容，并解释调整的理由。
**4）给后续步骤的开发说明：**
说明本步骤对外暴露了哪些供后续步骤使用的接口、以及已知遗留问题。

6. **产品应用平台**:当前项目开发产品面向个人用户、兼具轻量化落地能力，操作系统平台为windows。后续演进为企业级产品，平台变更为linux，因此开发过程所用组件和方案要考虑平台兼容性。

## 分步开发计划

### 步骤一：工程底座、动态配置中心、双模式文件存储抽象与分层元数据存储建设

#### 功能设计

1. **支持动态读写与热生效的全局配置管理功能**：集中管理系统的全部可配置参数，涵盖路径与存储配置（宿主机监控文件夹路径、托管工作区路径、本地索引与纯文本伴生镜像缓存路径、文档解析后端选型、向量存储驱动选型、对象存储驱动选型）、并发与网关配置（多进程并发工作数、外部消息网关凭证与白名单），以及明确细分的五类模型与权重配置块：第一类为文本推理与对话大语言模型（LLM）配置（负责语义元数据提炼、动态结构化抽取、智能体主循环推理及沙箱代码生成，包含服务商类型、服务地址、密钥、模型名称、最大上下文窗口与温度参数）；第二类为多模态视觉语言模型（VLM）配置（负责独立图片理解、文档内嵌图表转写与多模态视觉精筛核验，包含服务商类型、服务地址、密钥、视觉模型名称及最大输入图像分辨率限制）；第三类为文本向量嵌入模型（Embedding Model）配置（负责切片向量化入库与在线查询向量化，包含运行模式、服务地址与密钥、嵌入模型名称、向量维度 `embedding_dim` 一致性强制校验及批处理大小）；第四类为语义重排序模型（Reranker Model）配置（负责多路混合检索结果交叉编码重排，包含启用开关、运行模式、服务地址与密钥、模型名称及重排截断数量）；第五类为文档版面与 OCR 本地解析权重配置（负责 Docling 解析后端及本地 OCR 引擎所需的版面检测、表格结构识别与文字识别底层小模型，包含本地模型权重缓存目录路径与 `cpu`、`cuda` 或 `mps` 硬件推理加速设备选型）。该功能支持从本地配置文件初始化加载，并提供运行时的配置读取、参数合法性校验、敏感密钥脱敏展示、动态修改持久化写回以及核心组件热重载通知能力，供后续开发的外围客户端直接通过服务接口查看和修改系统配置。

2. **明确物理边界的双模式原始文件对象存储功能**：提供统一的文件注册、流式读取、本地路径定位、文件上传接收、文件复制与归档移动能力，并在架构上严格界定两种物理存储模式以适配四种外围交互端的不同部署拓扑：一是“宿主机原地引用模式”，指目标文件夹物理存储在核心服务守护进程所在宿主机可直接挂载读写的文件系统路径上（适用于同机 CLI、同机自托管桌面端 App 以及在 Web UI 或手机 IM 中直接指定宿主机已挂载的存量目录），系统直接原地扫描建索引、原地归档移动，不产生任何重复文件拷贝；二是“跨端上传托管归档模式”，指当目标文件或文件夹来自跨设备或浏览器的客户端流式上传（适用于 Web UI 客户访问端上传本地文件夹、手机 IM 聊天窗口直接发送文件附件）时，系统将其接收并存入服务端专门开辟的“托管归档工作区”中统一管理与索引。系统默认实现本地文件系统存储驱动，同时定义标准对象存储抽象接口以预留未来扩展接入 MinIO 等对象存储服务的能力。

3. **分层文件元数据存储管理与第一层系统基础属性采集功能**：对标主流文档智能系统的分层元数据架构（如 RAGFlow 的元数据管理体系），建立“两层通用元数据 + 三类模态专属结构摘要”的存储与多条件联合筛选体系，在本步骤直接完成“第一层系统基础属性”的自动采集，同时为后续步骤提供“第二层文档级语义增强元数据”以及“三类模态专属结构摘要”的标准化回填接口与基于哈希的文件路径同步能力。其中，“第一层系统基础属性”为所有文件共有并在本步骤直接采集，包含文件唯一标识、文件名称、文件扩展名、MIME 类型、文件字节大小、所属父目录路径、存储模式标识（“宿主机原地引用模式”或“跨端上传托管归档模式”）、用于增量变更检测与移动识别的 SHA-256 内容哈希值、文件系统创建时间与最后修改时间；“第二层文档级语义增强元数据”为所有文件共有并由步骤五统一提炼回填，包含开放域主题分类标签、百字核心摘要、关键命名实体与关键词列表、业务起止时间范围；“三类模态专属结构摘要”则按文件所属模态按需挂接且互不冗余，分别为“办公文档专属结构摘要”（由步骤二统计并回填）、“图像专属结构摘要”（由步骤三提取并回填）以及“表格专属结构摘要”（由步骤四提取并回填）。

4. **可插拔向量与全文索引存储及“纯文本伴生镜像缓存”管理功能**：管理文档、图像与表格解析后产生的结构化切片，完整记录每个切片所属的文件标识、切片顺序、起止页码或工作表名称、行列跨度、页面版面矩形坐标框、内嵌原图缓存路径、用于大模型阅读的原始结构化文本（如含合并单元格的 HTML 表格原文）以及用于索引匹配的去标签纯文本，同步提供数据库级的全文关键词倒排索引与高维稠密向量索引存储。同时，针对无法被操作系统文本扫描工具直接读取的二进制文件（PDF、Word、PPT、Excel 与图片），在本地索引缓存目录中统一维护按文件唯一标识命名、内部按页码或工作表行号标记的“纯文本伴生镜像缓存”，供步骤六的 ripgrep 极速搜索链路直接扫描并映射回源文件位置。系统默认实现基于 SQLite 的轻量级单文件混合索引存储驱动，同时定义统一的检索引擎抽象接口以预留未来扩展接入 Elasticsearch 等搜索引擎的能力。

#### 技术方案

1. **针对“支持动态读写与热生效的全局配置管理功能”的技术方案**：采用 Python 语言结合 Pydantic 强类型数据校验框架与 YAML 配置文件解析库，构建线程安全的全局配置管理中心。使用嵌套的 Pydantic 配置模型分别定义存储与路径配置、五类模型与解析权重配置（LLM、VLM、Embedding、Reranker、本地解析权重）及网关安全配置，内置向量维度一致性校验器与接口连通性探测方法。配置中心在启动时加载本地配置文件，对外提供脱敏配置导出、运行时增量更新、原子级文件持久化回写以及观察者模式的热重载通知机制，确保上层组件在配置变更时无需重启进程即可动态更新状态。

2. **针对“明确物理边界的双模式原始文件对象存储功能”的技术方案**：采用面向对象抽象基类定义虚拟文件存储抽象接口（声明文件流读取、宿主机原地路径注册、跨端上传流落盘写入、跨目录移动及 SHA-256 内容哈希计算契约），以预留未来扩展 MinIO 等对象存储的接口能力；当前阶段基于 Python 标准文件系统库完整实现默认的本地文件系统存储驱动，在驱动内部清晰维护“宿主机原地引用模式”路径白名单与“跨端上传托管归档模式”工作区目录。

3. **针对“分层文件元数据存储管理与第一层系统基础属性采集功能”的技术方案**：采用 Python 标准库中的操作系统文件状态接口（`os.stat` 与 `pathlib`）、MIME 类型探测库（`mimetypes`）与标准哈希库（`hashlib` 的 SHA-256 算法）实现“第一层系统基础属性”的确定性提取；选用 Python 内置的 SQLite 关系型数据库并开启预写式日志（WAL）高并发模式构建元数据存储中心。在数据库中设计通用元数据主表（承载所有文件共有的“第一层系统基础属性”与“第二层文档级语义增强元数据”）、模态专属摘要 JSON 扩展字段（按文件模态分别承载“办公文档专属结构摘要”、“图像专属结构摘要”或“表格专属结构摘要”）、关键词与标签倒排关联表以及切片明细表，并在文件类型、修改时间、文件大小、主题分类与业务起止时间范围上建立复合索引。同时实现基于 SHA-256 内容哈希值的路径原子级同步逻辑，当文件在后续被归档移动或回滚但内容哈希未变时，直接原地更新数据库中的路径记录。

4. **针对“可插拔向量与全文索引存储及纯文本伴生镜像缓存管理功能”的技术方案**：定义统一的全文与向量混合索引存储抽象基类接口（声明切片批量写入、按文件清理、BM25 全文检索、向量相似度近邻检索及结合关系型元数据的标量联合过滤契约），以预留未来扩展 Elasticsearch 等搜索引擎的接口能力；当前阶段基于 SQLite 内置的 FTS5 全文检索扩展（配合中英文分词器）与 sqlite-vec 向量扩展完整实现默认的本地混合索引存储驱动，并封装本地“纯文本伴生镜像缓存”读写管理器，在切片入库或清理时同步生成或删除对应二进制文件的 `.txt` 伴生镜像文件（每行以结构化前缀标注所属文件标识与页码或工作表行号）。

#### 验收标准

1. **五类模型与系统参数动态配置管理验证通过**：调用配置管理中心接口执行运行时参数修改（涵盖 LLM、VLM、Embedding、Reranker、本地解析权重及路径配置），验证非法配置项与不匹配的向量维度能被强类型校验准确拦截，合法配置修改能够自动持久化写回磁盘并触发热重载通知，且导出的公开配置已对敏感密钥完成掩码脱敏。

2. **双模式对象存储与第一层系统基础属性采集验证通过**：分别以“宿主机原地引用模式”注册本地存量文件、以“跨端上传托管归档模式”传入文件字节流，验证本地存储驱动能准确区分两种存储模式，自动提取出准确的文件字节大小、MIME 类型、SHA-256 内容哈希值及系统时间戳并存入数据库，且文件移动与哈希路径同步更新功能正常运转。

3. **分层元数据回填与多条件联合初筛验证通过**：调用元数据回填接口模拟写入“第二层文档级语义增强元数据”以及“办公文档专属结构摘要”、“图像专属结构摘要”、“表格专属结构摘要”，执行多条件复合过滤查询，验证筛选结果的准确率达到百分之百。

4. **全文、向量混合存取与纯文本伴生镜像缓存验证通过**：向 SQLite FTS5 与 sqlite-vec 混合索引存储层写入多条带有页码与版面坐标的测试切片及模拟向量，验证“纯文本伴生镜像缓存”文件同步生成，且分别执行 BM25 全文检索与带元数据过滤条件的向量近邻检索均能准确返回排序结果及完整的溯源定位信息。

### 步骤二：多源版面办公文档统一解析框架、内嵌图表表格还原与结构化切片管道

#### 功能设计

1. **可插拔文档解析引擎抽象与默认驱动功能**：建立统一的版面型办公文档解析框架，默认集成并实现 Docling 作为核心解析后端，同时定义标准化的解析器抽象接口以预留未来扩展接入 MinerU 与 DeepSeek-OCR2 等解析后端的能力。

2. **新旧两代办公文档格式无损定版兼容功能**：全面支持新旧两代办公文档格式（涵盖 `doc`、`docx`、`ppt`、`pptx`）。对于现代开放文档格式（`docx` 与 `pptx`），直接交由核心解析后端原生解析；对于传统的二进制字处理文档与演示文稿（`doc` 与 `ppt`），统一在进入解析流水线前静默定版渲染导出为版面完全锁定的“原生数字版 PDF 镜像”，再直接汇入后续的高速数字版 PDF 解析通道，确保原始分页页码、表格网格与幻灯片版面百分之百锁定无损。

3. **原生数字版 PDF 与扫描件 PDF 智能判定与差异化解析功能**：在解析 PDF 文档（含由 `doc`、`ppt` 定版生成的原生数字版 PDF）时，自动逐页识别其属于原生数字版页面还是扫描件页面，并执行针对性的解析路线。对于原生数字版页面，直接走关闭全页 OCR 的高速数字矢量解析通道，毫秒级提取底层原生字符流、标题层级与矢量表格结构（仅当页面局部内嵌了光栅图像或截图时才对该局部区域启用视觉识别）；对于扫描件页面、拍照单据、多栏复杂排版以及带印章的表单文档，自动启动高分辨率页面渲染、版面区域检测、阅读顺序还原、光学字符识别（OCR）、数学公式 LaTeX 还原以及复杂跨行跨列表格结构重建。

4. **“办公文档专属结构摘要”自动统计与回填功能**：在办公文档解析完成时，直接基于解析器产出的结构对象自动统计并提取文档的总页数或幻灯片总数、全文总字符数、主要语种标识、精确的文档载体类型标识（原生数字版、扫描件、图文混合版），以及内部是否包含表格、是否包含数学公式、是否包含统计图表或内嵌图片的布尔标志位，作为“办公文档专属结构摘要”回填至步骤一的元数据存储中心。

5. **内嵌表格零 Token 自适应双格式转换、内嵌图片四步转写与切片入库功能**：按照文档的自然章节树、幻灯片页码与独立版面元素进行智能语义切分，为每个切片注入章节层级前缀、精确页码编号及页面版面矩形坐标框，并对文档内的表格、数学公式与内嵌图片实施专门的结构化处理。第一，针对文档内嵌表格实施零 Token 微秒级自适应 HTML 与 Markdown 双格式转换：直接读取解析器内存中的表格单元格属性进行确定性复杂度判断（完全不调用大模型、不消耗任何 Token，单表判断耗时在微秒级），当表格满足存在跨行或跨列合并单元格（`row_span > 1` 或 `col_span > 1`）、存在两行及以上的多级嵌套表头、单元格内部包含多段换行或子列表、各行有效单元格跨度不一致的异形表单这四条确定性条件中的任意一条时，系统将其导出为保留 `rowspan` 与 `colspan` 属性的精简 HTML `<table>` 语法，仅当四条均不满足时导出为紧凑的 Markdown 表格语法。第二，针对文档内嵌图片与统计图表实施四步过滤与视觉转写链路：首先定位页面中的图片或统计图表区域（记录页码与版面坐标框）并裁剪导出为独立图片文件存入本地资产缓存目录；其次通过确定性的像素宽高阈值与跨页重复位置检测，自动过滤掉页眉徽标（Logo）、装饰小图标与细长分割线等无效装饰图，仅保留实质性的业务插图与统计图表；接着对保留的实质性内嵌图片调用本地 OCR 与多模态视觉语言模型（VLM）提取图中文字与数据趋势描述，同时自动抓取该图片在原文档中紧邻的图注标题及前后相邻段落构成上下文窗口；最后将“章节前缀 + 图注上下文 + 视觉描述 + 图内 OCR 文字”作为独立切片入库，并在切片记录中绑定裁剪后的原图缓存路径。在构建全文与向量索引时，自动剥离表格 HTML 标签并结合表头语义摘要计算稠密嵌入向量写入步骤一的混合索引库，同时将该办公文档解析出的全部页面正文、表格文本与内嵌图片描述按页码写入步骤一的“纯文本伴生镜像缓存”。

#### 技术方案

1. **针对“可插拔文档解析引擎抽象与默认驱动功能”的技术方案**：采用工厂模式定义文档解析抽象基类接口与统一的标准化解析输出结构（包含页面集合、章节层级树、带单元格跨度属性的表格对象集合、公式集合、内嵌图片集合及版面坐标框），预留扩展其他解析后端的插件注册点；当前阶段完整封装并实现默认的 Docling 解析驱动，从步骤一配置中心读取本地解析权重缓存路径与硬件推理加速设备配置。

2. **针对“新旧两代办公文档格式无损定版兼容功能”的技术方案**：针对现代开放格式文档（`docx` 与 `pptx`）直接调用 Docling 原生解析驱动提取文档对象模型中的段落、样式层级、表格、内嵌图片与幻灯片结构；针对传统二进制格式文档（`doc` 与 `ppt`），通过异步子进程调用系统本地无头模式的 LibreOffice 矢量打印引擎（执行 `--headless --convert-to pdf`），在临时工作区将其直接定版导出为包含完整原生字符流与矢量线条的原生数字版 PDF 文件，随后直接送入本步骤的 PDF 解析流水线，并在解析产出的所有切片与元数据中透明映射回原始 `doc` 或 `ppt` 文件路径。

3. **针对“原生数字版 PDF 与扫描件 PDF 智能判定与差异化解析功能”的技术方案**：利用轻量级 PDF 页面分析库（如 `PyMuPDF`）构建页面特征探针，在重度解析前逐页统计可直接提取的有效原生字符密度、字体编码完整度以及内嵌光栅图像的面积覆盖占比。当页面有效原生字符密度充足且无乱码字形时（包括所有由 `doc`、`ppt` 定版导出的数字页），判定为原生数字页，路由至关闭全页 OCR 的快速数字矢量解析通道直接提取原生文本与矢量表格；当页面无原生文本层或被大幅扫描图像覆盖时判定为扫描页，自动将其渲染为高分辨率图像并路由至开启版面分析、公式识别与表格网格重建的视觉 OCR 解析通道。

4. **针对“办公文档专属结构摘要自动统计与回填功能”的技术方案**：在解析管道后置处理阶段，直接读取标准化解析输出对象中的固有属性完成确定性统计：读取页面集合长度获得总页数，累加正文与表格纯文本获得总字符数，根据数字页与扫描页计数占比确定文档载体类型标识，根据字符 Unicode 区间分布判定主要语种，并直接检查解析产出的表格列表、公式列表与过滤后的实质性内嵌图片列表长度是否大于零以生成对应的布尔标志位，最后调用步骤一的元数据更新接口完成“办公文档专属结构摘要”回填。

5. **针对“内嵌表格零 Token 自适应双格式转换、内嵌图片四步转写与切片入库功能”的技术方案**：构建基于文档布局树的语义分块器、纯内存表格复杂度路由器与内嵌图处理器。普通正文按标题层级聚合并自动拼接章节面包屑前缀；遇到表格内存对象（`TableItem`）时，直接在内存中遍历其 `TableCell` 列表检查 `row_span > 1`、`col_span > 1`、表头行数大于 1、单元格文本含换行符或各行总列宽不一致四个布尔条件（零模型调用、零 Token 消耗），命中任意一条即序列化为仅保留 `<table>`、`<thead>`、`<tbody>`、`<tr>`、`<th>`、`<td rowspan="..." colspan="...">` 标签的精简 HTML 字符串，全部未命中则序列化为标准 Markdown 表格；遇到内嵌图片对象时，先检查裁剪图像的像素尺寸（剔除宽高小于阈值或长宽比失衡的装饰图及跨页固定位置页眉图），对保留的实质性图表调用本地 OCR 与步骤一配置的 VLM 接口生成视觉描述，拼接原文档紧邻的图注标题与前后段落文本并记录裁剪图本地缓存路径。最后，调用步骤一配置的文本向量嵌入模型批量计算所有切片的稠密向量，将切片写入混合索引库，并同步将该文档的全量解析文本按页码写入步骤一的“纯文本伴生镜像缓存”。

#### 验收标准

1. **新旧格式文档解析与定版 PDF 转换验证通过**：输入现代格式（`docx`、`pptx`）与传统二进制格式（`doc`、`ppt`）测试文档，验证系统对现代格式直接完成原生解析，对传统二进制格式通过无头 LibreOffice 定版导出为原生数字版 PDF 并走高速数字通道完成解析，页码边界与原文档完全一致。

2. **PDF 智能分流与“办公文档专属结构摘要”回填验证通过**：分别输入原生数字版多栏 PDF（含公式与统计图表）和扫描版复杂表单 PDF，验证系统准确识别两者的文档载体类型标识，且自动回填至数据库中的“办公文档专属结构摘要”（总页数、总字符数、主要语种及内部元素布尔标志位）完全准确。

3. **复杂表格零 Token HTML 还原、内嵌图片过滤转写与伴生镜像生成验证通过**：验证含跨行跨列合并单元格的表格在不调用大模型的情况下被微秒级自动序列化为保留 `rowspan` 和 `colspan` 的精简 HTML `<table>`，简单表格被序列化为 Markdown；验证文档中的页眉装饰小图标被自动过滤，而实质性统计图表被裁剪缓存、绑定图注上下文并生成视觉描述入库；同时验证该文档对应的“纯文本伴生镜像缓存”文件已准确生成。

### 步骤三：照片与图像文件多模态视觉理解与跨模态索引管道

#### 功能设计

1. **图像基础物理尺寸提取与内嵌文字 OCR 识别功能**：针对文件夹中的各类独立人物照片、图表截图、扫描单据与白板照片等图片文件，直接提取像素宽高分辨率、长宽比与 EXIF 拍摄时间等确定性物理属性，同时自动检测并识别图片中出现的全部印刷体或手写体文字内容（涵盖截图文字、图表坐标轴与图例文字、单据文字、白板书写文字）。

2. **基于视觉语言模型的结构化视觉特征与自然语言描述生成功能**：对标主流多模态文档系统（如 RAGFlow 的图片解析机制），采用步骤一配置的多模态视觉语言模型（VLM）配合标准化的结构化视觉分析提示词，对任意输入图片一次性提取开放域结构化视觉特征与详实的自然语言画面描述，准确识别图片的场景类别（如人物肖像照、数据统计图、架构流程图、票据单据、会议白板、自然风光）、画面主体与人物特征、背景颜色类别（如纯色背景的具体颜色类别或复杂自然背景）以及开放域视觉标签集合。

3. **“图像专属结构摘要”回填、伴生镜像生成与跨模态双路索引入库功能**：将提取出的像素宽高分辨率、长宽比、EXIF 拍摄时间、场景类别、背景颜色类别、人物主体特征及开放域视觉标签集合作为“图像专属结构摘要”回填至步骤一元数据存储中心及标签倒排关联表中；同时将生成的自然语言视觉描述文本与 OCR 识别出的图像内嵌文字合并作为该图片文件的检索切片，同步写入步骤一的全文 BM25 索引、稠密语义向量索引以及本地“纯文本伴生镜像缓存”，使系统能够通过任意自然语言视觉条件、图中文字或正则表达式精准检索目标图片。

#### 技术方案

1. **针对“图像基础物理尺寸提取与内嵌文字 OCR 识别功能”的技术方案**：采用 Python 的 Pillow 图像处理库直接读取图像文件的像素宽度、像素高度、长宽比计算值与 EXIF 原始拍摄时间戳，实现基础物理属性的零误差确定性获取；同时调用本地光学字符识别（OCR）引擎对图像执行文本检测与识别，按阅读顺序拼接提取出的文字内容并记录文字块坐标框。

2. **针对“基于视觉语言模型的结构化视觉特征与自然语言描述生成功能”的技术方案**：设计统一的多模态视觉理解调用接口，通过步骤一的配置管理中心对接本地推理服务运行的视觉语言模型（如 Qwen-VL、MiniCPM-V 等兼容接口）或云端多模态视觉大模型接口。设计通用的 JSON 结构化视觉提取提示词模板（Structured Vision Prompt Schema），引导视觉模型一次性输出包含 `scene_category`（场景类别）、`background_color`（背景颜色类别）、`subject_and_portrait`（核心主体与人物特征描述）、`visual_tags`（开放域视觉标签数组）以及 `detailed_caption`（完整自然语言画面描述）的固定结构数据；同时内置基于 OCR 文本与图像尺寸元数据的轻量级降级合成逻辑，确保在未配置视觉模型时依然能够生成基础可检索描述。

3. **针对“图像专属结构摘要回填、伴生镜像生成与跨模态双路索引入库功能”的技术方案**：调用步骤一元数据存储中心的更新接口，将 Pillow 提取的像素宽高分辨率、长宽比、EXIF 拍摄时间以及视觉语言模型输出的场景类别、背景颜色类别、人物主体特征封装为“图像专属结构摘要”写入该文件的模态专属扩展字段，并将 `visual_tags` 数组批量写入标签倒排关联表；同时将 `detailed_caption` 视觉描述文本与 OCR 识别出的内嵌文字拼接为完整索引切片，调用步骤一配置的文本向量嵌入模型生成稠密向量后存入混合索引库，并将该文本同步写入该图片文件对应的本地“纯文本伴生镜像缓存”。

#### 验收标准

1. **图像物理属性、OCR 文字与“图像专属结构摘要”回填验证通过**：输入多张不同类型的测试图片（涵盖不同背景颜色的人物照片、带文字的数据统计图表截图、单据照片与风景照），验证通过 Pillow、OCR 与视觉模型提取出的“图像专属结构摘要”（像素宽高分辨率、长宽比、EXIF 拍摄时间、场景类别、背景颜色类别、人物主体特征与开放域视觉标签集合）均准确无误并回填至元数据库，同时生成了对应的“纯文本伴生镜像缓存”。

2. **自然语言跨模态图像检索验证通过**：针对已入库的测试图片集，分别使用不同的自然语言视觉条件（如按特定背景颜色与人物特征、按图表趋势内容、按图中特定文字）执行检索，验证目标图片均能排在首位准确召回。

### 步骤四：CSV 与 Excel 表格文件通用结构画像、自适应表格切片与双层索引管道

#### 功能设计

1. **多工作表与异构表格原生直读及基础结构探测功能**：支持自动识别 CSV 与 TSV 文件的字符编码及分隔符，支持原生直接读取新旧两代 Excel 工作簿（`xlsx` 与 `xls`）中的全部工作表，并自动检测 Excel 工作表中是否包含跨行或跨列合并单元格。离线入库阶段聚焦提取所有结构化表格百分之百共有的通用基础结构信息：工作表名称列表、表头列名集合、各列数据类型映射（数值型、文本型、日期时间型、布尔型）、数据总行数与总列数、各列缺失值计数以及首尾样本行摘要。

2. **大小表双层通用索引构建（含小型表格 HTML / Markdown 自适应转换）与“表格专属结构摘要”回填功能**：针对不同规模的表格实施大小表双层索引策略，并与步骤二的合并单元格处理逻辑保持严格一致。第一，针对行数较少的小型表格，执行与步骤二一致的“HTML 与 Markdown 自适应双格式策略”：对于天然无合并单元格的纯文本小型 CSV / TSV 文件，或经底层引擎检测确认无合并单元格的小型 Excel 工作表，直接转化为紧凑的 Markdown 表格切片；一旦检测到小型 Excel 工作表内部存在跨行或跨列合并单元格，则直接按照合并区间将其序列化为保留 `<td rowspan="..." colspan="...">` 的精简 HTML `<table>` 切片入库，确保合并表头与单元格统属关系百分之百不丢失。第二，针对行数众多的大型数据表，将工作表名称列表、表头列名集合、各列数据类型映射、数据总行数与总列数、各列缺失值计数以及前五行样本数据组装成一份精炼的“数据表通用结构摘要卡”写入全文与向量索引库，同时将上述结构化统计信息作为“表格专属结构摘要”回填至步骤一的元数据存储中心；原始 CSV 纯文本文件保持原位直接供后续在线计算沙箱与 ripgrep 原地读取，而对于二进制格式的 Excel 文件（`xlsx` 与 `xls`），同步将其各工作表文本按工作表名与行号导出至步骤一的“纯文本伴生镜像缓存”，从而使 ripgrep 极速搜索链路也能直接检索二进制 Excel 中的任意数据行。

#### 技术方案

1. **针对“多工作表与异构表格原生直读及基础结构探测功能”的技术方案**：基于 Python 的 Pandas 数据分析库构建通用表格直读解析器，针对现代 `xlsx` 格式调用 `openpyxl` 引擎（同步读取工作表对象的 `ws.merged_cells.ranges` 属性零成本检测是否存在合并单元格），针对传统二进制 `xls` 格式直接调用 `xlrd`（读取 `sheet.merged_cells` 属性）或高性能 `python-calamine` 原生引擎毫秒级直读，针对 CSV 文件实现多字符编码（UTF-8、GB18030、GBK）自适应回退读取与分隔符自动嗅探。直接调用 Pandas 标准确定性接口获取通用结构特征：调用 `df.columns` 获取表头列名集合，调用 `df.dtypes` 获取各列数据类型映射，调用 `df.shape` 获取数据总行数与总列数，调用 `df.isna().sum()` 获取各列缺失值计数，调用 `df.head(5)` 获取前五行样本行摘要。

2. **针对“大小表双层通用索引构建与表格专属结构摘要回填功能”的技术方案**：根据设定的行数阈值自动分流：当工作表行数低于小型表格阈值时，检查合并单元格区间集合是否非空——若非空则根据合并区间坐标将单元格渲染为带 `rowspan` 和 `colspan` 属性的精简 HTML `<table>` 字符串（计算检索向量时剥离 HTML 标签），若为空则直接渲染为标准 Markdown 表格切片；当工作表行数高于阈值时，通过模板渲染器将工作表名称列表、表头列名集合、各列数据类型映射、数据总行数与总列数、各列缺失值计数以及前五行样本数据合成为高可读性的“数据表通用结构摘要卡”文本切片（若检测到表中包含日期时间类型列，顺带提取该列的首尾最小最大时间值供范围检索参考）。随后调用步骤一配置的文本向量嵌入模型计算语义向量存入混合索引库，调用元数据更新接口回填“表格专属结构摘要”与列名倒排关联表，并针对二进制 Excel 文件将其工作表行文本同步写入本地“纯文本伴生镜像缓存”。

#### 验收标准

1. **新旧格式表格原生直读与“表格专属结构摘要”回填验证通过**：向解析管道输入多工作表 `.xlsx`、传统二进制 `.xls` 以及不同编码的 `.csv` 测试文件，验证系统直接原生读取成功，且通过 Pandas 标准接口提取并回填至元数据库中的“表格专属结构摘要”（工作表名称列表、表头列名集合、各列数据类型映射、数据总行数与总列数、各列缺失值计数及首尾样本行摘要）完全准确。

2. **小型合并单元格 Excel 转 HTML 与大表结构摘要索引验证通过**：输入包含跨行跨列合并单元格的小型 Excel 工作表，验证其被准确序列化为保留 `rowspan` 与 `colspan` 的精简 HTML `<table>` 切片；输入包含上万行记录的大型 CSV 文件与大型 Excel 文件，验证索引库中仅生成了精简的“数据表通用结构摘要卡”切片而未产生逐行冗余向量，且二进制 Excel 已同步生成对应的“纯文本伴生镜像缓存”。

### 步骤五：第二层文档级语义增强元数据提炼与多进程并行增量索引引擎

#### 功能设计

1. **“第二层文档级语义增强元数据”结构化高速提炼功能**：对标主流文档智能系统（如 RAGFlow 的 Extractor 与 Auto Metadata 机制），将前序步骤的文档、图像与表格解析产出物统合起来，在不将长文档全文送入大模型的前提下，通过抽取高密度内容骨架，为所有类型的文件统一提炼并回填“第二层文档级语义增强元数据”。具体包含四项所有文件共有的核心语义字段：一是开放域主题分类标签（如技术规范、合同协议、财务单据、个人证照、学术论文、业务数据表等），直接支撑后续按主题检索过滤与文件夹自动归类；二是概括文件核心内容的百字核心摘要；三是文件中出现的关键命名实体与关键词列表（如机构名称、项目名称、人员姓名、核心统计指标名）；四是文件内容所记载事件的业务起止时间范围（独立于文件系统创建时间的业务周期）。

2. **全格式文件统一路由、增量变更检测与按需即时索引功能**：自动扫描目标文件夹及其子目录，根据文件类型自动分发至步骤二（版面办公文档）、步骤三（照片与图像）或步骤四（CSV 与 Excel 表格）解析管道；通过比对修改时间戳与 SHA-256 内容哈希值，自动跳过未变更文件，识别仅发生位置移动的文件并原地同步更新数据库路径，仅对真正新增或修改的文件执行解析，同时清理已删除文件的残留索引与“纯文本伴生镜像缓存”；此外提供面向指定局部文件夹的“按需即时增量索引”能力，确保在线工具访问任意尚未入库的文件夹时能够即时完成增量建库。

3. **多进程与异步并发结合的任务并行化索引加速功能**：针对包含数千个异构文件的文件夹，采用多进程并行解析与异步批量向量化入库相结合的任务并行化架构，充分调用多核计算资源提升建库速度，同时具备实时进度跟踪、单文件异常隔离（单个损坏文件报错不中断整体流程）以及断点续传能力。

#### 技术方案

1. **针对“第二层文档级语义增强元数据结构化高速提炼功能”的技术方案**：采用“高密度骨架抽样 + 结构化模型输出（Structured Outputs）+ 标准日期解析库”的技术路线。首先从步骤二、三、四的解析结果中仅抽取文件名、所属父目录名、文档各级章节标题树、首页前段摘要区文本、表格表头列名集合与首尾样本行以及图像视觉描述，组装成不超过一千词元的精炼文档骨架；接着调用通用日期时间解析库（如 `dateparser` 结合标准日期正则匹配）扫描文件名与文档骨架，自动提取并归一化出标准 ISO 格式的业务起止时间范围；随后调用步骤一配置的文本推理大语言模型（LLM）接口并启用强制 JSON Schema 结构化输出模式，对文档骨架执行一次极短上下文推理，一次性确定性生成包含开放域主题分类标签、百字核心摘要、关键命名实体与关键词列表、业务起止时间范围的“第二层文档级语义增强元数据”，调用步骤一接口写入元数据主表及关键词标签倒排关联表。

2. **针对“全格式文件统一路由、增量变更检测与按需即时索引功能”的技术方案**：构建统一的文件扫描与状态比对调度器，遍历目标目录树并与步骤一元数据库中的 SHA-256 内容哈希值记录进行比对：哈希值与路径均未变的文件直接跳过；哈希值相同但路径改变的文件直接调用步骤一的哈希路径同步接口原地更新路径而跳过重解析；仅将新哈希值文件加入待解析队列，并暴露可由在线原子工具随时调用的局部目录即时增量索引方法。

3. **针对“多进程与异步并发结合的任务并行化索引加速功能”的技术方案**：采用“多进程并行解析池 + 主进程批量向量化与单连接事务写入”的生产者-消费者流水线架构。利用 Python 多进程池并发执行耗费 CPU 的版面文档解析、图像 OCR、表格 Pandas 统计与骨架抽样，并为每个文件任务设置独立超时与异常捕获；主进程通过异步队列收集各工作进程返回的结构化元数据与切片文本，按固定批次大小集中调用步骤一配置的文本向量嵌入模型计算向量，最后在单一数据库连接事务中批量写入 SQLite 元数据表、全文索引表与向量表，既实现高吞吐并行加速，又规避多进程并发写 SQLite 引发的数据库锁冲突。

#### 验收标准

1. **“两层通用元数据”与“三类模态专属结构摘要”全链路闭环验证通过**：对包含数字版 PDF、扫描件 PDF、Word（`doc` 与 `docx`）、PPT（`ppt` 与 `pptx`）、照片图片、CSV 与 Excel（`xls` 与 `xlsx`）的混合测试文件夹执行索引构建，验证数据库中每个文件的“两层通用元数据”（“第一层系统基础属性”与“第二层文档级语义增强元数据”）及对应文件类别的“三类模态专属结构摘要”（“办公文档专属结构摘要”、“图像专属结构摘要”或“表格专属结构摘要”）均已完整且准确地提取入库。

2. **多进程并行加速与异常隔离验证通过**：在测试目录中混入人为损坏的异常文件启动并行索引引擎，验证多进程并发正常完成、数据库零锁冲突，损坏文件被准确隔离记录且不影响其余正常文件入库。

3. **增量跳过、移动识别与按需索引验证通过**：二次运行索引引擎验证未变更文件百分之百秒级跳过；移动部分文件位置后再次运行，验证系统通过 SHA-256 内容哈希值识别自动更新路径而未触发重复解析。

### 步骤六：多路并行混合检索引擎与可解释性溯源证据链系统

#### 功能设计

1. **职责边界清晰的四路并行混合搜索功能**：当收到在线搜索请求时，系统利用并行化机制同时启动四条互补的检索链路，每条链路各司其职。第一路是结构化元数据与标签初筛链路（检索 SQLite 关系表），支持基于“两层通用元数据”（如文件扩展名、文件字节大小、最后修改时间、开放域主题分类标签、关键命名实体与关键词列表、业务起止时间范围）与“三类模态专属结构摘要”（如文档载体类型标识、背景颜色类别、开放域视觉标签集合、表头列名集合）在关系型数据库中精确过滤缩小候选文件范围。第二路是 BM25 全文关键词搜索链路（检索 SQLite FTS5 倒排索引表），基于中英文分词倒排索引，对已入库的文档去标签切片、文档内嵌图描述、独立图像描述以及表格通用结构摘要卡进行自然语言多词组合高召回匹配与词频相关性打分。第三路是稠密向量语义搜索链路（检索 sqlite-vec 向量表），调用步骤一配置的文本向量嵌入模型将查询意图转化为稠密向量，在向量空间中执行跨模态语义相似度检索。第四路是操作系统级 ripgrep 极速字节流搜索链路（直接扫描本地磁盘文本文件与“纯文本伴生镜像缓存”），与第二路基于分词的数据库检索形成严密互补，专门负责复杂正则表达式匹配（如匹配特定格式的编码、单据号、日期格式正则）、不受分词器切碎影响的精确子串匹配，以及对未全量写入数据库的万行级大型 CSV 原始数据行的毫秒级逐行定位；由于 ripgrep 是直接扫描文件的纯文本工具且默认跳过二进制文件，系统严格界定其扫描目标范围为两个明确目录：一是直接原地扫描目标文件夹中的原生纯文本类文件（涵盖 `.csv`、`.tsv`、`.txt`、`.md`、`.json`，从而完整覆盖大型 CSV 的每一行原始数据），二是扫描步骤二、三、四为二进制文件（PDF、Word、PPT、Excel 与图片）生成的本地“纯文本伴生镜像缓存”目录，并在命中镜像文件行后自动将其映射还原为原始二进制文件的真实路径、页码或工作表行号。

2. **多路结果去重融合与语义重排序功能**：将四条并行搜索链路召回的候选文件与切片按唯一标识去重合并，融合不同搜索链路的排序信号，并调用步骤一配置的语义重排序模型（Reranker Model）结合深度语义相关性进行精细重排，输出最契合查询意图的 Top-K 检索结果。

3. **透明可解释的检索依据封装功能**：针对每一条返回的检索结果，强制生成结构化的“检索依据包”。每个依据包完整包含唯一依据编号、源文件名称、本地完整文件路径、存储模式标识、文件类型、在原文件中的精确位置（PDF 或办公文档的页码、PPT 的幻灯片页码、Excel 或 CSV 的工作表名与起止行号、页面版面矩形坐标框、内嵌图片裁剪缓存路径）、命中的原文内容摘录（若命中复杂表格则同时携带保留合并单元格的 HTML 表格原文，若命中图片则携带视觉描述摘要，若命中大表则携带表头与命中数据行），以及透明的命中原因说明（标示该依据来自哪一条或哪几条搜索链路及匹配得分）。

#### 技术方案

1. **针对“职责边界清晰的四路并行混合搜索功能”的技术方案**：基于 Python 异步并发机制编排四路检索协程。在接收到包含自然语言查询、关键词、正则表达式及元数据过滤条件的检索请求后，若指定了尚未入库的目标文件夹则先自动触发步骤五的按需即时增量索引，随后并发启动：1）SQLite 元数据主表与标签关联表联合过滤查询；2）SQLite FTS5 全文 BM25 检索；3）sqlite-vec 向量余弦相似度近邻检索；4）通过异步子进程调用操作系统的 ripgrep 工具（开启 `--json` 行流与行号输出模式，同时内置基于 Python 多线程与内存映射 `mmap` 的原生文本与正则扫描器作为兼容后备），同时将扫描目标指向用户目标文件夹下的原生文本文件（通过 `--glob` 限定 `.csv`、`.tsv`、`.txt`、`.md`、`.json` 等纯文本扩展名）以及本地“纯文本伴生镜像缓存”目录，解析输出的 JSON 匹配行前缀，将伴生镜像命中记录实时还原为对应二进制源文件的标识、页码或工作表行号。

2. **针对“多路结果去重融合与语义重排序功能”的技术方案**：采用倒数秩融合算法（RRF）将全文搜索排名、向量余弦相似度排名、ripgrep 扫描匹配排名与元数据命中权重进行无量纲归一化融合；随后根据步骤一配置的语义重排序模型（Cross-Encoder Reranker）开关与参数，对融合后的候选切片文本与用户查询意图执行交叉编码语义打分并截取 Top-K 结果。

3. **针对“透明可解释的检索依据封装功能”的技术方案**：定义标准化的检索依据数据结构，在检索结果返回前自动关联查询元数据主表与切片明细表，将源文件路径、存储模式标识、精确页码或工作表行列区间、版面坐标框、内嵌原图缓存路径、召回链路标签及原始结构化文本快照封装为统一的依据对象，同时提供面向大模型上下文的带编号引用文本格式化方法与面向前端界面的结构化 JSON 序列化方法。

#### 验收标准

1. **四路并发执行、大型 CSV 原地行扫描与伴生镜像映射验证通过**：运行混合检索测试，验证一次查询请求能够同时并发触发元数据过滤、BM25 全文搜索、向量语义搜索与 ripgrep 极速搜索四条链路；验证 ripgrep 链路既能直接命中上万行大型 CSV 文件第数千行中的特定编号或正则模式，又能通过扫描“纯文本伴生镜像缓存”准确命中 PDF、Word、Excel 二进制文档中的特定正则字符串并正确还原出源文件路径与页码/行号。

2. **跨模态通用检索与 Reranker 重排验证通过**：在混合测试库上分别测试按视觉特征与场景描述检索图片、按文档内嵌图表内容检索办公文档、按表头列名检索数据表以及按专业术语与复杂表格内容检索 PDF 文档，验证经多路融合与语义重排序后目标文件均排在前列准确返回。

3. **可解释性检索依据完整性验证通过**：检查所有返回的检索依据包，确认依据编号、源文件路径、精确页码或行号、版面坐标框、命中链路说明及原文快照字段百分之百完整且与源文件事实严格一致。

### 步骤七：高内聚通用原子工具集、受控动态编码沙箱与智能体技能自进化引擎

#### 功能设计

1. **统一多模态混合检索工具功能**：将步骤六的底层四路并行混合检索引擎封装为面向智能体大模型（Function Calling）的标准参数化搜索工具。支持大模型在推理时动态传入自然语言查询意图、关键词列表、正则表达式、限定文件夹路径以及任意“两层通用元数据”与“三类模态专属结构摘要”过滤条件，返回匹配的文件清单及带编号的可解释性检索依据包。

2. **文档深度检视与零样本动态结构化抽取工具功能**：作为连接非结构化版面文档（PDF、Word、PPT、单据）与结构化数据处理的跨领域通用桥梁，提供两项相辅相成的核心能力。第一项能力是“文档深度检视（定向翻页完整精读）”，用于解决检索切片仅有局部几百字碎片、无法看清跨页完整上下文的问题；当大模型根据初步检索依据发现某篇文档的关键条款、跨页大表或实验推导横跨多个页面或章节时，可调用该模式直接指定目标文档路径与起止页码、章节标题或表格序号，一次性完整拉取连续多页的全文内容与保留了合并单元格的完整 HTML 表格进行深度精读。第二项能力是“零样本动态结构化抽取（运行时按需定义表头、跨多份文档批量抠取字段成表）”，工具代码内部不预设任何固定行业字段，具备完全的跨行业通用性；当用户要求从几十份同类或异构文档中批量提取特定信息（例如从多份简历 PDF 中提取“姓名、最高学历、毕业院校、工作年限”，或从多份采购合同 Word 中提取“甲方、乙方、合同总金额、签署日期”，或从多份财务单据 PDF 中提取科目名称与金额指标）时，由智能体大模型在运行现场临时构造一份自定义的“目标字段名、数据类型与提取说明清单（JSON Schema）”连同目标文档列表传入本工具；工具自动并发扫描每一份目标文档中的正文段落与 HTML 表格，将符合该临时字段清单的数据逐篇提取出来，组装为规整的二维结构化数据表（每行记录自动绑定源文件路径与页码依据），并通过内部数据集缓存句柄机制零损耗传递给后续的“通用表格探查与受控沙箱动态编程计算工具”执行汇总计算、导出 Excel/CSV 或写入 SQL 数据库。

3. **通用表格探查与受控沙箱动态编程计算工具功能**：专门面向 CSV、Excel 以及由“文档深度检视与零样本动态结构化抽取工具”生成的数据集缓存句柄，提供“先探查真实数据形态、再临时编写代码动态处理”的完全通用计算能力。该工具分为两步通用机制：第一步支持智能体调用“数据探查模式”读取目标表格的表头列名集合、各列数据类型映射、各列缺失值计数及前五行样本行摘要，现场摸清该表格的具体数据形态；第二步支持智能体根据探查到的真实结构与用户自然语言需求，现场临时编写标准的 Python（Pandas / NumPy）数据处理脚本或 DuckDB SQL 查询语句，在安全的受控计算沙箱中运行以完成任意复杂的行列重塑、任意时间频率的重采样聚合、多列排序、缺失值数学插值补全、多表关联及分组统计计算，并支持将处理结果直接导出为指定路径的 CSV 文件、Excel 工作簿，或直接写入任意指定的 SQL 数据库表中。

4. **动态规则文件系统分类与安全归档工具功能**：提供通用的文件夹自动化整理、子目录创建、文件复制、移动与批量归类能力。支持基于“第一层系统基础属性”归类（如按文件扩展名、修改时间区间、文件字节大小），也支持基于“第二层文档级语义增强元数据”归类（自动汇总目标文件夹下全部文档的开放域主题分类标签与百字核心摘要，聚类归一化为互不重叠的顶层主题类别文件夹后批量移动文件）。内置预演模式与操作事务日志，支持按事务标识一键全量回滚恢复原始目录状态，并在移动或回滚后自动通过 SHA-256 内容哈希值匹配同步更新索引库中的文件路径。

5. **多模态视觉精筛与图表核验工具功能**：针对初步检索出的候选独立图片或步骤二裁剪缓存的文档内嵌统计图表，支持传入任意自然语言视觉核验条件（如二次核验图片背景颜色纯度、人物主体完整性、构图特征，或读取文档内嵌复杂折线图、柱状图中的具体数值点），调用步骤一配置的多模态视觉语言模型（VLM）执行高精度视觉复核并返回带依据的结论。

6. **跨通道消息与文件主动投递工具功能**：作为专供智能体大模型按需主动调度的外部推送原子工具，严格与系统底层的“第一轨常规响应原路返回管道”划清职责边界——常规问答的文本回复与检索依据由步骤八守护进程沿当前请求的 HTTP/SSE 连接自动原路返回给当前提问端，无需调用本工具；仅当大模型在用户指令中识别出明确的“跨通道投递意图”（例如在本地交互端要求将找到的文件或生成的报表发送到手机端）或“向手机 IM 聊天窗口主动上传发送本地实体图片、文档或表格附件意图”时，大模型才主动调用本工具，将目标文件本地路径、附加说明文本、目标接收通道标识（如 Telegram、企业微信、飞书、钉钉或桌面系统通知）以及关联的检索依据包组装为标准投递事件，发布至步骤八核心服务的“第二轨跨通道通知与文件主动投递事件总线”，交由下游对应的通道服务消费并执行物理文件上传推送。

7. **智能体技能自进化与沉淀功能（构建本地“用户自进化技能库”）**：对标前沿终身学习智能体架构（如 Voyager 技能库与模块化 `SKILL.md` 规范），系统自动追踪并记录智能体每次成功完成的任务轨迹（包含用户意图、工具调用链、在计算沙箱中临时编写并验证通过的 Python 数据处理脚本、动态抽取的 JSON 字段结构模板）。当检测到某类特定数据处理逻辑或业务抽取工作流被同一用户高频重复调用，或用户明确发出保存技能指令时，自进化引擎自动将该临时脚本或工作流进行参数化抽象重构（剥离硬编码的文件路径与固定常数，提取为带标准入参的可复用函数），自动生成包含技能名称、适用场景描述、输入参数规范的标准化技能说明文档（`SKILL.md`）与配套可执行脚本，持久化保存至本地的“用户自进化技能库”中并建立技能检索索引，实现“高频能力按用户习惯自动生长、低频偶发需求由沙箱动态编码解决”的自演进闭环。

#### 技术方案

1. **针对“统一多模态混合检索工具功能”的技术方案**：基于 Pydantic 构建强类型的工具参数声明与统一的工具返回结构（包含执行状态、结果摘要、产出文件路径列表、数据集引用句柄、事务标识与检索依据列表），将步骤六的四路并行混合检索引擎封装为标准原子工具注册至工具中心，并在检测到目标文件夹存在未入库文件时自动调用步骤五的按需即时增量索引能力。

2. **针对“文档深度检视与零样本动态结构化抽取工具功能”的技术方案**：提供 `read_pages`（定向翻页精读）与 `batch_extract`（零样本动态结构化批量抽取）两种执行入口。在定向翻页精读入口中，根据传入的文件标识与页码范围或章节名，直接从切片表读取连续页面的完整正文与未截断的 HTML 表格原文；在零样本批量抽取入口中，采用异步并发信号量机制结合步骤一配置的 LLM 结构化输出能力（Structured Outputs）实现 Map-Reduce 抽取流水线——接收大模型在运行时动态生成的目标字段 JSON Schema 定义与文件列表后，并发读取各份文档的相关页面与 HTML 复杂表格完成字段抠取，自动在每条提取结果行中注入源文件路径与页码依据，并将全量提取记录集写入工作区内存与临时 Parquet/JSON 数据集缓存总线，生成唯一的轻量级数据集引用句柄返回给智能体，避免大批量数据行经由大模型上下文复制中转导致词元溢出或数字失真。

3. **针对“通用表格探查与受控沙箱动态编程计算工具功能”的技术方案**：基于 Pandas、NumPy、openpyxl、xlrd、python-calamine、DuckDB 与 SQLAlchemy 构建“先探查后动态编码执行”的受控数据处理引擎。工具提供 `inspect`（探查）与 `execute`（执行）两种操作模式：在探查模式下快速返回指定 CSV、Excel 或数据集缓存句柄的表头列名集合、各列数据类型映射、各列缺失值计数与前五行样本行摘要；在执行模式下，接收智能体现场临时生成的 Python Pandas 数据处理代码或 DuckDB SQL 语句，先通过 Python 抽象语法树（AST）静态安全审计拦截一切系统命令执行、进程派生、网络请求与越权目录访问，随后在注入了预加载数据帧（`df`）与受限科学计算库命名空间的子进程隔离沙箱中执行代码，捕获标准输出与异常堆栈，并通过统一导出器将结果数据帧保存为 CSV、Excel 或通过 SQLAlchemy 写入目标 SQL 数据库表。

4. **针对“动态规则文件系统分类与安全归档工具功能”的技术方案**：结合标准文件系统操作库与步骤一、步骤五的元数据中心实现安全归档引擎。当执行按主题归类时，采用“两阶段全局主题聚类归一化”逻辑：第一阶段确保目录内全部文件已完成骨架抽样与“第二层文档级语义增强元数据”提取，第二阶段将目录内所有开放域主题分类标签聚类收敛为清晰的顶层目录集合后再执行文件移动。每次批量文件移动均在 SQLite 事务日志表中持久化记录每个文件的原路径与目标路径映射以支持幂等一键回滚，并在物理移动完成后立即调用步骤一的哈希路径同步接口原地更新索引库路径。

5. **针对“多模态视觉精筛与图表核验工具功能”的技术方案**：封装针对单张或多张候选独立图片及步骤二裁剪缓存的文档内嵌图表原图的多模态视觉推理调用逻辑，通过向步骤一配置的 VLM 接口传入高清原图与用户指定的细粒度核验问题（如核验照片背景纯度或读取统计图表指定坐标点数值），返回结构化核验结论与检索依据包。

6. **针对“跨通道消息与文件主动投递工具功能”的技术方案**：构建标准化跨端投递事件发布器。工具接收大模型传入的目标文件本地路径列表、消息说明文本、目标通道类型（支持指定具体 IM 平台通道、默认关联手机通道、当前会话来源 IM 通道或桌面通知）及关联检索依据包，校验本地文件可读性后组装为标准投递事件载荷，发布至核心服务的“第二轨跨通道通知与文件主动投递事件总线”（WebSocket 广播队列），由已连接的下游 ACP 消息网关或桌面端通知监听器实时消费投递。

7. **针对“智能体技能自进化与沉淀功能”的技术方案**：在本地工作区构建结构化的“用户自进化技能库”目录与 SQLite 技能注册表。每次智能体主循环成功执行完包含沙箱动态编码或多步工具编排的任务后，轨迹记录器将用户意图向量、工具调用序列与沙箱验证通过的 Python 代码写入执行历史表；当同类意图聚类频次达到设定阈值或收到显式沉淀指令时，调用大模型代码重构提示词将临时脚本改写为接收标准字典参数的纯函数模块，自动进行一次沙箱干跑语法校验（Dry-Run AST & Execution Check），校验通过后生成包含 YAML 元数据头（名称、描述、参数 Schema）与使用指南的 `SKILL.md` 文件及配套 `.py` 脚本存入“用户自进化技能库”，并注册为智能体可直接检索和调用的扩展技能。

#### 验收标准

1. **六个基础原子工具通用性与正交性验证通过**：检查工具注册中心，确认基础操作严格收敛为六个通用原子工具，无任何针对单一业务场景硬编码的冗余工具，且所有工具返回结构均完整携带检索依据包。

2. **文档定向精读、动态结构化抽取与数据集句柄流转验证通过**：测试调用“文档深度检视与零样本动态结构化抽取工具”的定向精读模式拉取指定页码完整上下文与 HTML 表格；测试向批量抽取模式动态传入不同领域的自定义字段结构声明（如从多份包含复杂合并单元格表格的测试 PDF 文档中提取指定指标），验证生成的轻量级数据集引用句柄可直接传入“通用表格探查与受控沙箱动态编程计算工具”，并百分之百保真地导出为汇总 Excel、CSV 文件及写入 SQL 数据库表中。

3. **沙箱先探查后临时写代码动态处理表格验证通过**：验证智能体能够先调用探查模式摸清 CSV 表头与样本形态，再现场编写 Pandas 代码放入受控沙箱执行，准确完成多维表格结构重塑、时间序列频率重采样、排序以及缺失值数学插值补全任务，且恶意系统调用代码被 AST 审计百分之百拦截。

4. **“用户自进化技能库”沉淀与复用验证通过**：模拟用户连续执行同类表格转换或数据提取任务（或下达保存技能指令），验证自进化引擎能自动将临时编写的沙箱代码抽象重构为带参数规范的 `SKILL.md` 与可执行脚本存入本地“用户自进化技能库”，并在后续同类请求中直接命中并调用该自进化技能一步完成处理。

5. **文件夹多维归类、路径同步与一键回滚验证通过**：在混合测试目录上分别执行按文件属性归类与按语义主题聚类归类，验证子文件夹创建、文件归档及数据库索引路径同步全部准确；随后执行回滚操作，验证所有文件与数据库路径百分之百恢复原状。

### 步骤八：在线智能体主循环、自进化技能调度与本地核心服务守护进程

#### 功能设计

1. **通用智能体主循环自主规划、多步工具编排与自进化技能优先复用功能**：构建在线部分的核心大脑，接收用户的任意自然语言办公指令（涵盖多模态知识库 RAG 问答与复杂的多步文档操作任务）。主循环在规划阶段同步检索步骤七的六个基础原子工具与本地“用户自进化技能库”：若命中已沉淀的成熟用户技能，则优先加载并调用该技能脚本快速执行；若为全新或偶发任务，则通过“意图理解、任务规划拆解、动态生成原子工具调用参数或临时沙箱代码、观察执行结果与错误自修复、触发高频技能自进化评估、汇总生成最终回复”的闭环机制自主完成任务。

2. **在线并发任务调度与实时状态流推送功能**：当主循环面对涉及多路检索、跨大批量文档抽取或复杂表格沙箱计算的任务时，自动开启并发工具调度；同时在任务执行全过程中实时向外流式推送细粒度的阶段状态信息（如正在执行四路混合检索、正在并发抽取文档进度、正在探查表格并编写沙箱代码、正在调用自进化技能、正在触发跨通道文件投递）。

3. **答案透明性与检索依据强制展示门禁功能**：主循环内置可解释性强制审计机制。凡是在完成问答或操作任务的过程中调用了检索或文档检视工具，最终生成的回复中必须自动绑定并展示结构化的“检索依据列表”，清晰呈现每处结论或提取数据所对应的源文件路径、页码或行列范围、匹配链路及原文快照，确保输出结果的透明可溯源。

4. **本地核心服务守护进程、全功能管理接口与双轨响应分发功能**：将离线索引引擎、在线智能体主循环、本地“用户自进化技能库”管理、文件安全回滚以及步骤一的全局配置管理中心统一封装为常驻后台的本地标准服务守护进程，作为 CLI、Web UI、桌面端 App 与 ACP 协议消息网关唯一共享的通信底座。守护进程在通信架构上严格区分并协同运行双轨分发机制：一是系统底层固定的“第一轨常规响应原路返回管道”，每次请求处理完毕后，守护进程自动将回答正文、思考轨迹与结构化检索依据沿着当前请求的 HTTP 或 SSE 流式连接原路下行返回给发起该请求的客户端（CLI、Web UI、桌面端 App 或 ACP 网关）；二是由智能体大模型主动调用步骤七“跨通道消息与文件主动投递工具”触发的“第二轨跨通道通知与文件主动投递事件总线”（WebSocket 广播流），专门用于将本地检索到的实体图片或新生成的 Excel/CSV 报表主动推送至订阅该总线的外部通道（如 ACP 协议消息网关的手机 IM 会话或桌面系统通知）。守护进程完整暴露五大类标准网络接口：全局系统配置读写与五类模型连通性测试接口、离线知识库监控（区分“宿主机原地引用模式”目录与“跨端上传托管归档模式”目录）与增量索引管理接口、在线智能体同步与流式任务执行及“用户自进化技能库”管理接口、本地源文件与内嵌图安全预览下载及归档事务回滚接口，以及“第二轨跨通道通知与文件主动投递事件总线”接口。

#### 技术方案

1. **针对“通用智能体主循环自主规划、多步工具编排与自进化技能优先复用功能”的技术方案**：采用 ReAct（推理与行动）与 Plan-and-Execute（规划与执行）相结合的架构构建智能体主控制器。抽象统一的大模型调用层，通过步骤一的配置管理中心动态读取“文本推理与对话大语言模型（LLM）配置”对接本地推理引擎（如 Ollama、vLLM）或兼容 OpenAI 协议的云端接口，并内置用于离线自动化测试的确定性工具编排仿真器。主循环在每轮规划前先对本地“用户自进化技能库”执行意图匹配，将匹配到的 `SKILL.md` 注入上下文供大模型直接调用；当执行沙箱动态编码或既有技能遇到数据异常报错时，主循环捕获异常堆栈并在步数上限内自动修正代码重试，任务成功后异步通知步骤七的技能自进化引擎记录轨迹。

2. **针对“在线并发任务调度与实时状态流推送功能”的技术方案**：基于 Python 异步事件循环与异步生成器机制构建任务执行流。当主循环拆解出可并行的子任务时通过异步任务组并发调用底层工具，同时在每个阶段切换点产出标准化的进度事件对象，供上层流式接口实时消费。

3. **针对“答案透明性与检索依据强制展示门禁功能”的技术方案**：在智能体会话上下文状态机中设立专门的溯源证据收集池，自动拦截并汇总当前轮次所有工具调用返回的检索依据包；在生成最终回复的后置审计阶段，强制校验正文中引用角标与证据池的对应关系，并将结构化检索依据数组封装进最终响应载荷中。

4. **针对“本地核心服务守护进程、全功能管理接口与双轨响应分发功能”的技术方案**：采用 FastAPI 框架配合异步 ASGI 服务器（如 Uvicorn）构建无界面依赖的本地核心服务守护进程。使用 RESTful 接口规范实现系统配置在线读写热更新、宿主机目录树安全浏览、跨端文件流式上传托管、知识库索引触发与统计查询、“用户自进化技能库”列表管理、文件流预览下载及事务回滚接口；使用 Server-Sent Events（SSE）流式协议实现“第一轨常规响应原路返回管道”，向当前请求客户端实时推送思考轨迹、最终回答与检索依据；使用 WebSocket 协议配合内存异步发布-订阅队列实现“第二轨跨通道通知与文件主动投递事件总线”，将大模型主动调用“跨通道消息与文件主动投递工具”产出的文件发送事件实时广播给已连接的 ACP 消息网关与桌面通知端。

#### 验收标准

1. **五类模型配置在线改配与热生效验证通过**：通过网络客户端调用守护进程的配置管理接口，验证可在线读取脱敏配置、分别修改五类模型（LLM、VLM、Embedding、Reranker、本地解析权重）或系统参数并立即热生效。

2. **多模态文档操作、自进化技能复用与知识库 RAG 问答全链路验证通过**：通过守护进程接口分别输入跨模态图片查找并跨端投递、文件夹按文件属性与语义主题自动归类、跨多份复杂版面 PDF 动态抽取结构化指标导出 Excel/CSV 并写入 SQL 数据库、CSV 多维数据表重采样重塑排序、CSV 缺失值数学插值补全以及多模态知识库问答指令，验证智能体主循环均能自主规划工具链或调用“用户自进化技能库”准确产出目标结果。

3. **双轨分发边界与检索依据百分之百随路展示验证通过**：验证所有常规问答与操作结果均通过“第一轨常规响应原路返回管道”（HTTP/SSE）返回当前请求端，同时大模型调用“跨通道消息与文件主动投递工具”时能准确通过“第二轨跨通道通知与文件主动投递事件总线”（WebSocket）触发跨端文件推送；检查所有响应报文，确认均包含完整的结构化检索依据列表。

### 步骤九：独立 CLI 终端交互工具开发

#### 功能设计

1. **无 UI 环境交互式多轮会话与流式状态展示功能**：面向 Linux 服务器、远程 SSH 终端或本地命令行等无图形界面环境，提供独立的纯终端交互式命令行会话界面，支持用户输入自然语言问答或文档处理指令，通过核心服务“第一轨常规响应原路返回管道”在终端中动态展示智能体的思考进度、正在调用的工具或自进化技能名称及格式化渲染的最终回答。

2. **宿主机本地目录原地操作、单行命令批处理与脚本集成功能**：明确界定 CLI 模式下目标文件夹的物理内涵——由于 CLI 直接运行于核心服务宿主机终端（或 SSH 会话），用户在命令行传入的文件夹路径直接对应核心服务宿主机的本地文件系统路径，默认采用零拷贝“宿主机原地引用模式”进行即时索引、检索、原地归档或生成新表格文件（同时支持通过命令行参数将外部文件导入“跨端上传托管归档模式”目录）。支持单行非交互式命令执行，并支持切换人类易读的富文本表格输出模式与机器易读的纯 JSON 输出模式。

3. **命令行系统配置管理与“用户自进化技能库”管理功能**：提供专门的命令行配置与技能管理子命令，允许用户在终端内直接通过命令查看和修改全部系统配置参数（含 LLM、VLM、Embedding、Reranker 与本地解析权重五类模型配置、路径配置及网关配置）、触发模型与后端连通性测试，以及查看、启用、禁用或导出本地已沉淀的“用户自进化技能库”。

4. **终端检索依据透明展示与原文溯源检视功能**：每次完成涉及检索的问答或操作后，在终端回答下方自动渲染结构清晰的“检索依据明细表格”，展示依据编号、匹配文件路径、所在页码或行号、命中搜索链路以及命中原文片段；支持通过命令按编号在终端内直接展开查看对应依据的完整切片原文（含表格结构）。

5. **终端知识库索引管理与归档事务回滚功能**：支持在命令行中直接指定宿主机文件夹启动增量或全量索引、实时显示解析进度条、查看已入库文件统计报表，以及查询历史文件归档记录并按事务标识一键执行回滚。

#### 技术方案

1. **针对“无 UI 环境交互式多轮会话与流式状态展示功能”的技术方案**：在独立的命令行客户端工程目录下，基于标准 HTTP 与 SSE 流式客户端库对接步骤八本地核心服务守护进程的网络接口，不直接跨目录导入核心层内部数据库类或其余三个外围客户端代码。利用 Python 终端交互框架（如 Typer 结合 Rich 终端富文本渲染库）构建交互式会话循环，实时消费“第一轨常规响应原路返回管道”的 SSE 事件流并在终端内动态刷新思考状态面板与 Markdown 格式回答。

2. **针对“宿主机本地目录原地操作、单行命令批处理与脚本集成功能”的技术方案**：通过命令行参数解析器封装单次非交互式执行入口，自动将用户传入的相对路径解析为宿主机绝对路径后作为“宿主机原地引用模式”目录传给守护进程接口；在请求完成后根据格式标志位输出富文本或标准 JSON 字符串，并以标准操作系统退出码反映任务执行成败。

3. **针对“命令行系统配置管理与用户自进化技能库管理功能”的技术方案**：封装专用的配置管理与技能管理子命令，直接调用守护进程的配置读写、连通性测试与“用户自进化技能库”列表管理接口，在终端内将层级化的系统配置（含五类模型配置参数）与已沉淀技能清单渲染为清晰的键值表格，并支持通过命令行参数直接提交修改。

4. **针对“终端检索依据透明展示与原文溯源检视功能”的技术方案**：解析守护进程原路响应报文中的结构化检索依据数组，使用终端表格组件在回答末尾自动绘制包含依据编号、源文件路径、位置区间、召回链路与原文摘要的边框表格，并提供依据详情查看子命令调用文件切片详情接口展示完整上下文。

5. **针对“终端知识库索引管理与归档事务回滚功能”的技术方案**：封装索引管理与事务回滚子命令，对接守护进程的索引触发、进度轮询、统计查询与事务回滚接口，使用终端进度条组件实时展示千级文件并行解析百分比，并支持按事务编号一键触发文件夹归档还原。

#### 验收标准

1. **零 UI 依赖与客户端彻底解耦验证通过**：检查确认 CLI 客户端代码与其他三个外围客户端完全解耦，且在无任何图形显示服务的纯字符终端环境下全部功能运行流畅。

2. **命令行在线配置与“用户自进化技能库”管理验证通过**：在终端内通过子命令查看、修改系统配置参数（含五类模型配置）并管理“用户自进化技能库”列表，验证修改直接通过守护进程生效并落盘。

3. **宿主机目录原地处理与溯源表格展示验证通过**：通过 CLI 指定宿主机测试目录执行知识库问答、跨文档数据提取与 CSV 数据处理指令，验证终端清晰输出执行结果、生成文件路径以及包含源文件路径、页码/行号和原文摘要的检索依据表格，且归档回滚命令验证通过。

### 步骤十：独立 Web UI 浏览器交互工作台开发（基于 React + Vite）

#### 功能设计

1. **双模式文件夹选择（宿主机目录树原地选择 + 客户访问端文件夹上传托管）与流式对话监控功能**：开发与 CLI 完全独立、面向现代浏览器的可视化网页交互工作台。鉴于现代浏览器受安全沙箱限制无法直接暴露客户访问端磁盘的真实绝对路径，且用户可能同机访问或局域网跨机访问，Web UI 在文件夹选择上明确提供双入口：一是“宿主机目录树选择器”，供用户直接在网页上浏览并勾选核心服务宿主机已挂载的存量文件夹（走“宿主机原地引用模式”，直接原地索引与处理数千个存量文件）；二是“客户访问端文件夹流式上传入口”，当待处理文件位于客户访问端电脑时，支持用户通过浏览器文件夹上传控件或拖拽方式将整个文件夹批量流式上传至核心服务的托管工作区（走“跨端上传托管归档模式”）。对话界面实时以可折叠步骤卡片与时间轴形式动态展示“第一轨常规响应原路返回管道”推送的智能体推理进度、四路并行检索状态、正在调用的工具或自进化技能详情以及生成的结果文件一键下载链接。

2. **分屏联动的可解释性检索依据预览台功能**：采用“左侧对话与任务流、右侧多模态检索依据与源文件预览台”的双栏分屏布局。每次回答正文中的引用角标与下方的“检索依据卡片列表”均清晰标明源文件名、完整路径、精确页码或行列范围、命中搜索链路及原文摘要。用户点击任意引用角标或依据卡片时，右侧预览台立即联动打开对应的源文件：针对 PDF 与办公文档展示对应页码内容、渲染保留了合并单元格的 HTML 表格、展示裁剪缓存的文档内嵌图表并高亮展示命中原文片段；针对独立照片与图片文件直接展示高清原图及“图像专属结构摘要”标签；针对 CSV 与 Excel 表格文件（含小型合并单元格 HTML 表格、源数据表及沙箱处理生成的新报表）直接以交互式数据网格形式展示表头与数据行，并提供一键下载与归档后文件夹打包下载入口。

3. **可视化知识库全景看板、“用户自进化技能库”管理中心与归档事务管理功能**：在网页端提供图形化的知识库与技能管理视图，以统计卡片与分布图表展示已索引文件总数、各文件类型占比、文档载体类型分布及开放域主题分类统计；提供可视化的“用户自进化技能库”管理面板，展示智能体已根据用户习惯自动沉淀的全部技能卡片（支持在线查看 `SKILL.md` 说明、演进版本与启用状态切换）；支持在网页上实时查看增量索引进度条，以及可视化浏览历史文件归类记录并一键点击回滚恢复。

4. **可视化系统设置中心面板功能**：在网页端提供专门的可视化系统配置界面，用户可通过直观的分组标签页、下拉框、开关和表单输入，直接在浏览器中在线查看和修改五类模型与解析权重配置（文本推理 LLM、多模态视觉 VLM、向量嵌入 Embedding、语义重排 Reranker、本地版面与 OCR 权重目录及加速设备）、宿主机监控路径、文档解析后端、向量存储驱动、对象存储驱动、并发进程数以及外部消息网关白名单，并支持点击测试按钮实时验证各模型与服务的连接有效性。

#### 技术方案

1. **针对“双模式文件夹选择与流式对话监控功能”的技术方案**：在独立的网页客户端工程目录下，采用 **React + Vite** 现代前端技术栈构建单页应用（SPA），与 CLI、桌面端 App 及消息网关代码完全解耦。封装对接守护进程宿主机目录列表接口的模态目录树选择组件（对应“宿主机原地引用模式”），同时利用浏览器原生目录上传属性（`webkitdirectory`）与多文件流式分块上传接口将客户访问端本地文件夹上传至服务端托管工作区（对应“跨端上传托管归档模式”）；通过 `fetch` 与 `EventSource` 流式接口消费守护进程“第一轨常规响应原路返回管道”的 SSE 事件流，实时渲染思考时间轴、Markdown 回答与数学公式表格。

2. **针对“分屏联动的可解释性检索依据预览台功能”的技术方案**：基于 React 组件化状态管理构建双栏联动布局与多模态文件预览容器。当用户点击某条检索依据时，前端请求守护进程的文件安全预览接口，根据文件的类型标识动态切换 React 渲染视图：文档类视图定位展示对应页码切片、版面坐标框、保留合并单元格的 HTML 表格、内嵌图片裁剪原图与高亮原文；图像类视图直接加载原图流并渲染“图像专属结构摘要”徽章；表格类视图解析 CSV 或 Excel 数据流（兼容合并单元格 HTML 表格渲染）并展示为支持表头固定与行高亮的交互式数据网格组件，同时提供结果文件直接下载按钮。

3. **针对“可视化知识库全景看板、用户自进化技能库管理中心与归档事务管理功能”的技术方案**：基于 React 构建知识库统计仪表盘、“用户自进化技能库”详情抽屉组件、增量索引进度轮询钩子（Hooks）以及历史归档事务时间轴列表，直接对接守护进程的索引统计、自进化技能管理与事务回滚 RESTful 接口。

4. **针对“可视化系统设置中心面板功能”的技术方案**：基于 React 构建分组式受控配置表单组件（划分为 LLM 配置、VLM 配置、Embedding 配置、Reranker 配置、本地解析权重与加速配置、存储与网关配置六个子面板），对接守护进程的配置读取、更新与连通性测试接口，实现网页端一键保存与后台热生效。

#### 验收标准

1. **React + Vite 独立运行及双模式文件夹选择验证通过**：确认 Web UI 工程采用 React + Vite 构建且与其余外围客户端零耦合；在浏览器中分别测试“勾选宿主机存量目录原地索引处理”与“从浏览器上传客户机本地文件夹至托管工作区处理”，验证两种模式均运行顺畅且结果文件可正常下载。

2. **网页端五类模型可视化设置与“用户自进化技能库”管理验证通过**：在网页系统设置中心通过图形表单分别查看与修改五类模型及系统配置参数并点击保存，验证后台配置实时热生效并持久化；在“用户自进化技能库”管理面板中验证可正常浏览和启停已沉淀的专属技能。

3. **分屏联动预览与复杂 HTML 表格、内嵌图表渲染验证通过**：在网页端执行知识库问答、跨模态找图、文档数据抽取与 CSV 表格处理指令，验证点击检索依据角标或卡片时右侧预览台能准确切换展示原图、文档内嵌统计图、含合并单元格的 HTML 表格高亮片段或交互式数据网格。

### 步骤十一：独立跨平台桌面端 App 开发（基于 Electron）

#### 功能设计

1. **独立桌面端全功能多模态工作台、“用户自进化技能库”管理与原生系统设置中心功能**：开发与 CLI 及 Web UI 完全独立、互不依赖的跨平台原生桌面端应用程序。提供独立的原生桌面窗口，完整包含流式多模态对话中心、任务轨迹监控、检索依据分屏预览器、知识库管理看板、“用户自进化技能库”管理面板以及可视化的桌面端系统设置中心（支持在桌面端窗口内直接通过图形界面对文本推理 LLM、多模态视觉 VLM、向量嵌入 Embedding、语义重排 Reranker、本地解析权重以及存储网关等全部配置项进行修改与连通性测试）。

2. **系统托盘常驻、守护进程同机自托管与全局快捷键呼出功能**：支持将桌面端应用最小化常驻操作系统托盘后台运行，并在桌面端启动时自动检测、拉起与托管同机本地核心服务守护进程的生命周期；支持通过全局键盘快捷键在操作系统任意界面随时呼出轻量级“桌面悬浮快捷指令框”，让用户在浏览本地文件夹或编辑文档时无需切换主窗口即可随时下达检索或处理指令。

3. **同机原生文件夹拖拽原地入库与系统文件资源管理器一键定位源文件功能**：明确界定桌面端 App 下目标文件夹的物理内涵——由于桌面端 App 与其自托管的核心服务守护进程天然运行在同一台个人电脑上，用户从操作系统桌面或文件管理器中拖拽进桌面端窗口（或通过系统原生文件对话框选中）的任意文件夹，直接就是核心服务守护进程可原地读写的同机真实绝对路径，天然采用零拷贝“宿主机原地引用模式”立即触发增量索引或针对该文件夹原地执行归类、抽取、计算等操作；在展示任何一条检索依据卡片或处理完生成的结果文件时，提供“在系统文件夹中定位源文件”按钮，点击后直接拉起操作系统的原生文件资源管理器打开对应目录并高亮选中该本地文件。

4. **双轨联动操作系统级原生消息通知功能**：同时对接“第一轨常规响应原路返回管道”的完成状态与“第二轨跨通道通知与文件主动投递事件总线”，当后台执行的千级文件批量索引、跨多份文档结构化抽取汇总、大型表格沙箱计算任务完成，或者智能体主动触发桌面端通知投递时，主动弹出操作系统原生桌面通知提醒用户。

#### 技术方案

1. **针对“独立桌面端全功能多模态工作台、用户自进化技能库管理与原生系统设置中心功能”的技术方案**：在独立的桌面端工程目录下，明确采用 **Electron** 跨平台桌面框架构建独立桌面应用程序（严禁依赖 CLI 模块或外部 Web UI 服务进程）。通过 Electron 主进程（Main Process）、预加载安全桥接脚本（Preload Script）与渲染进程（Renderer Process）架构，对接同机运行的核心服务守护进程本地网络接口，集成完整的双栏对话与多模态证据预览视图、“用户自进化技能库”管理视图以及涵盖五类模型与系统参数的可视化配置表单。

2. **针对“系统托盘常驻、守护进程同机自托管与全局快捷键呼出功能”的技术方案**：利用 Electron 主进程的 `Tray`、`Menu`、`globalShortcut` 与多 `BrowserWindow` 管理接口，实现系统托盘常驻图标、全局键盘快捷键监听与无边框悬浮快捷输入窗口切换；在 Electron 主进程启动生命周期中集成核心服务守护进程的健康检查与子进程自托管逻辑，若检测到本地核心服务未运行则自动在后台静默拉起守护进程，应用退出时安全回收子进程资源。

3. **针对“同机原生文件夹拖拽原地入库与系统文件资源管理器一键定位源文件功能”的技术方案**：利用 Electron 的进程间通信（IPC）与原生系统模块（`dialog.showOpenDialog` 及拖拽文件对象的真实路径获取能力），直接提取被拖入或选中的本机文件夹真实绝对路径，以“宿主机原地引用模式”传给同机核心服务接口直接执行索引或操作；同时在主进程中调用 Electron 原生的 `shell.showItemInFolder(fullPath)` 接口，跨平台（Windows、macOS、Linux）直接拉起操作系统原生文件管理器打开对应目录并高亮选中目标源文件或生成的结果文件。

4. **针对“双轨联动操作系统级原生消息通知功能”的技术方案**：在 Electron 主进程中订阅守护进程的“第二轨跨通道通知与文件主动投递事件总线”（WebSocket）并监听长耗时任务完成状态，调用 Electron 原生的 `Notification` 模块弹出包含任务摘要与结果本地路径的操作系统级桌面通知，支持用户点击通知直接唤起主窗口或打开对应文件位置。

#### 验收标准

1. **Electron 桌面端彻底解耦与同机自托管独立运行验证通过**：确认桌面端工程基于 Electron 构建，不依赖 CLI 与外部 Web UI 服务进程，能够独立启动并自动拉起托管同机核心服务完成全部交互。

2. **原生系统设置（含五类模型配置）与文件夹拖拽原地处理验证通过**：在桌面端设置中心修改五类模型或系统配置项并验证生效；将本机测试文件夹直接拖入 Electron 桌面窗口，验证能立即识别本机真实绝对路径并以“宿主机原地引用模式”触发离线索引或文档处理任务，无多余文件拷贝。

3. **系统资源管理器一键定位源文件与原生通知验证通过**：完成一次多模态问答或数据抽取任务后，点击检索依据卡片上的“定位源文件”按钮，验证通过 Electron `shell.showItemInFolder` 正确拉起操作系统文件管理器定位到对应的本机源文件，且任务完成或跨端通知触发时正常弹出系统原生通知。

### 步骤十二：独立 ACP 协议消息网关与第三方 IM 平台连通开发

#### 功能设计

1. **标准化 ACP 协议消息路由、双模式目录映射与会话管理功能**：开发与其他外围交互端（CLI、Web UI、桌面端 App）完全独立、基于 ACP（智能体通信协议）的消息网关服务。定义统一的跨平台智能体通信消息信封格式，将来自不同第三方即时通讯（IM）平台的外部消息统一转换为标准化 ACP 请求并转发至本地核心服务守护进程。明确界定手机 IM 跨设备场景下的文件夹交互内涵：一方面支持用户在手机聊天窗口中直接通过自然语言指定核心服务宿主机已挂载或已配置的文件夹名称（走“宿主机原地引用模式”远程操控服务端存量目录）；另一方面支持用户在手机聊天窗口中直接向机器人发送图片、PDF 文档或 CSV/Excel 表格附件（网关自动接收附件并存入核心服务的托管工作区，走“跨端上传托管归档模式”触发即时解析与处理）。

2. **Telegram、企业微信、飞书、钉钉四大平台可插拔连接器功能**：内置面向 Telegram、企业微信、飞书、钉钉的四大官方开放平台独立通道适配器。支持用户在手机端聊天窗口中直接发送自然语言指令或文件附件，远程驱动本地办公助手执行知识库问答、跨模态文件检索、文档归类、表格沙箱计算或数据抽取汇总任务。

3. **双轨协同响应与多模态文件跨端主动投递功能**：清晰协同步骤八守护进程的双轨分发机制：一方面，对于智能体执行任务后通过“第一轨常规响应原路返回管道”（HTTP/SSE）返回的常规文本回答与结构化检索依据，网关自动将其渲染为适配对应手机 IM 平台的富文本或折叠溯源卡片消息回复至当前手机聊天窗口；另一方面，网关后台常驻监听步骤八的“第二轨跨通道通知与文件主动投递事件总线”（WebSocket）——无论用户最初是从本地 CLI、Web UI、桌面端 App 下达了将文件发送到手机端的跨通道指令，还是直接在手机 IM 窗口下达了需要回传物理文件附件的指令，一旦智能体大模型主动调用了步骤七的“跨通道消息与文件主动投递工具”并向事件总线发布投递事件，网关立即消费该事件，自动从核心服务磁盘流式读取目标图片或沙箱新生成的 Excel/CSV 报表文件，调用对应第三方 IM 平台的媒体与文件上传接口直接发送到用户的手机聊天窗口中，并同步附上标明源文件位置、页码与匹配详情的检索依据卡片。

4. **外部接入安全鉴权与授权白名单控制功能**：提供严格的外部 IM 用户账号白名单校验、平台回调签名验证与访问权限控制机制（相关平台凭证与授权白名单支持通过全局配置管理中心统一在线配置），确保只有用户本人授权绑定的手机账号才能触发本地文件检索、上传托管附件与接收文件投递，严密保护个人数据隐私。

#### 技术方案

1. **针对“标准化 ACP 协议消息路由、双模式目录映射与会话管理功能”的技术方案**：在独立的消息网关工程目录下构建异步网关服务，不依赖其余三个客户端的任何代码。设计标准化的 ACP 入站与出站消息信封模型（包含协议版本、平台通道标识、发送方身份标识、会话上下文标识、指令正文、入站附件流、结构化检索依据摘要块及本地文件附件路径列表）。当入站消息包含用户在手机端发送的文件或图片附件时，网关先调用守护进程的托管文件上传接口将其存入服务端托管工作区（“跨端上传托管归档模式”）并获取托管路径，再连同用户指令一并提交给守护进程任务执行接口。

2. **针对“Telegram、企业微信、飞书、钉钉四大平台可插拔连接器功能”的技术方案**：采用插件化适配器模式定义统一的即时通讯通道抽象基类，规范入站消息与附件接收解析、富文本与交互式卡片发送、图片媒体上传发送以及通用文档上传发送接口。在此基础上分别基于四大平台官方开放 API 实现连接器：对接 Telegram Bot 官方接口（支持 Webhook 与长轮询模式及图片文档双向收发）、对接飞书开放平台官方接口（支持事件订阅、租户令牌管理、图片与文件双向收发及含折叠检索依据的交互式卡片推送）、对接钉钉开放平台官方机器人接口（支持流式通道与 Webhook 签名校验及媒体文件双向收发），以及对接企业微信官方开放接口（支持企业微信自建应用消息回调验证、访问令牌管理以及图文卡片与临时素材文件上传推送）。

3. **针对“双轨协同响应与多模态文件跨端主动投递功能”的技术方案**：网关同时维护面向守护进程的“第一轨常规响应原路返回管道”HTTP/SSE 请求客户端与“第二轨跨通道通知与文件主动投递事件总线”WebSocket 常驻订阅协程。对于常规请求，通过第一轨接收最终文本回答与检索依据并格式化回推；一旦第二轨 WebSocket 协程收到由大模型调用“跨通道消息与文件主动投递工具”触发的投递事件载荷，立即根据目标通道标识路由至对应的平台连接器（Telegram、企业微信、飞书或钉钉），流式读取本地磁盘上的目标图片或新生成的表格文件完成分块上传与消息投递，并将随路携带的检索依据包渲染为手机端易读的溯源说明卡片一并发送。同时，为确保在尚未配置公网商业平台密钥的本地开发环境下也能百分之百完成闭环测试，内置一个完整遵循 ACP 协议的本地离线手机端沙箱模拟器，真实执行文件流上传接收、图片落盘校验与消息卡片渲染。

4. **针对“外部接入安全鉴权与授权白名单控制功能”的技术方案**：在网关入站中间件层实现统一的加密签名验证器与发送方账号白名单拦截器，实时从步骤一与步骤八的全局配置管理中心同步已授权的用户标识列表；任何未在白名单内或签名校验失败的外部请求均在网关边缘直接拒绝并记录安全审计日志，严禁转发至本地核心服务。

#### 验收标准

1. **网关独立性与安全白名单拦截验证通过**：确认消息网关工程与 CLI、Web UI、桌面端 App 完全解耦；使用未在授权白名单中的外部账号模拟发送检索指令，验证网关立即拦截拒绝并记录审计日志，未向核心服务转发请求。

2. **跨端指令操控宿主机目录与手机发送附件托管处理双向验证通过**：一方面通过 IM 通道发送指令按视觉条件检索宿主机存量目录中的目标图片并跨端投递、或跨多份 PDF 文档动态抽取结构化指标汇总为表格投递，另一方面模拟从手机聊天窗口直接发送一份含缺失值的 CSV 附件要求执行插值计算并发回，验证系统均能全自动完成检索或沙箱处理，并通过“第二轨跨通道通知与文件主动投递事件总线”将目标图片、生成的表格文件以及标明源文件位置与页码的检索依据卡片成功发送到用户的手机端通道。

3. **Telegram、企业微信、飞书、钉钉四大官方平台连接器协议契约验证通过**：分别运行针对 Telegram、企业微信、飞书、钉钉四个通道适配器的消息转换、签名校验、附件接收、图片上传与文件投递契约测试，验证全部测试项百分之百通过。
